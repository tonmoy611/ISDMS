# ISDMS project state (end of Phase 13)
Completed: Phase 01 foundation, Phase 02 authentication, Phase 03 permissions and user management, Phase 04 university structure, Phase 05 students, Phase 06 email/SMS, verification and password reset, Phase 07 courses, Phase 08 sections and schedule, Phase 09 enrollment, Phase 10 attendance, Phase 11 results, Phase 12 documents, Phase 13 finance.
Stack: Node/Express (backend/), React+Vite+react-router (frontend/), MySQL; migrations in database/migrations (npm run migrate); bootstrap admin: npm run create-admin.
Backend layout: src/app.js; config/{env,db}.js (db exports pool, withTransaction); utils/{AppError,logger,asyncHandler,password,tokens,cookies}.js;
 middleware/{requestId,errorHandler,csrfGuard,authenticate,authorize}.js; services/{audit,authService}.js; routes/index.js mounts routes/v1/{health,system,auth}.js.
Conventions: response { success, data } or { success:false, error:{code,message,details?,requestId} }. Protect routes with authenticate() then authorize('role'...). Super Admin always passes authorize. Use writeAudit({ctx,userId,action,...}) for sensitive actions.
Auth: httpOnly cookies isdms_at (access JWT, 15 min) and isdms_rt (opaque refresh, hashed in DB, rotated). Users with must_change_password are refused by authenticate() except /auth/me and /auth/change-password.
Status values: pending_verification (cannot log in yet; Phase 11 adds first-time verification), active, blocked, inactive.
DB tables: schema_migrations, universities, system_settings, roles (super_admin, teacher, staff, student), users, refresh_tokens, audit_logs.
Frontend: context/AuthContext.jsx, services/api.js (auto-refresh on 401), components/{Navbar,Footer,SystemStatus,ProtectedRoute,AppLayout,Field}, pages/{Landing,Login,ChangePassword,Dashboard}.
Env: JWT_SECRET required (32+ chars); CORS_ORIGINS must include the site origin in production.
Not yet built: forgot/reset password, email/SMS, first-time verification, fine-grained permissions, user management.

Phase 03 additions:

Phase 11 additions:
Backend: services/resultRules.js (PURE: UGC_DEFAULT_SCALE, scaleProblems, gradeFor, computeTotals, parseMark, semesterGpa, cgpa, summarizeStudent), services/resultService.js, routes/v1/results.js. Section-level access (teacher of the section, results.manage, results.view) is decided in sectionCtx(); correction and scale routes use requirePermission.
Flow: result_batches.status draft -> submitted -> published (one batch per section). Submit computes rows in `results` (letter, points, is_pass snapshot). Publish writes result_history v1 and sets enrollments.outcome ('passed'/'failed') for still-enrolled students. Corrections: result_corrections (changes JSON [{componentId, oldMarks, newMarks}], one pending per result via generated pending_key); approve applies marks, recomputes with the CURRENT scale, adds a history version.
Separation of duties: publisher != submitter; approver != requester (no exceptions, even Super Admin).
Contract for transcripts and documents: use resultService.studentResults(student) (published results only; semesters with GPA, CGPA, credits earned/attempted). Retake rule: latest attempt wins. Admit cards can use attendanceService.studentSummary for eligibility.
Contract for finance: nothing in results; fees can gate result visibility later by filtering at studentResults().
Frontend: pages ResultsHome (tabs: sections, corrections, grading scale), ResultSheet, Corrections, GradeScale, MyResults (/my-results), StudentResults (/students/:id/results); components/ResultsView.jsx. MyClasses links to the sheet.
Known gaps: no incomplete (I), withdrawn (W) or absent grades; no grace marks or moderation; no improvement-exam rules; no per-course pass-mark separate from the scale; no results by batch or program report and no merit list; no email or notice on publication (notice phase will add it); no CSV import of marks (the migration phase will); a correction can change marks but not components; reopening deletes unpublished computed rows and recomputes at next submit; dropped students keep their draft marks but are excluded.
